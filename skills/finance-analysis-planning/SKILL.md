name: 金融分析规划
description: 用于股票、公司财务、公告、公司业务、竞对格局、行业研究、行情估值分析与投资相关事实分析的 planner skill；不用于简单价格或行情报价查询。
when_to_use: 用户要求调研股票、上市公司、财报、估值分析、公司业务、竞对现状、产品市场景气、公告、行业地位、金融资产走势原因、风险或投资相关事实分析。简单询问、单点价格、当前行情报价或“看看/查询某资产多少钱”不使用本 skill，除非用户明确要求分析、研究、报告、证据整理、原因解释、趋势判断、投资建议、多维对比或生成文档/附件。
skill_type: planner
user_invocable: false
disable_model_invocation: true
routing_summary: 适用于股票和上市公司调研、财务表现分析、行情估值分析、公司业务、竞对格局、产品市场景气、公告事件梳理、行业地位和投资风险分析等金融研究任务；不适用于简单询问型价格/行情报价查询。
planning_guidance: |
  金融分析和股票调研任务必须优先规划为“证据收集 + 最终聚合”，不要让最终回复直接依赖松散的网页来源列表。

  如果当前请求只是简单询问型请求，不应选择或使用本 skill。简单询问型请求是指用户只要求单点事实、当前值、简短结果或直接答案，例如“看看/查询/告诉我/现在多少/今天多少/有没有/是什么”等表达；即使需要搜索或实时信息，也应交给通用 Planner 生成轻量 read 节点，不要生成 evidence_claims.md。
  只有当用户明确要求分析、研究、报告、证据整理、原因解释、趋势判断、投资建议、多维对比、多指标拆解或生成文档/附件时，才使用本 skill。

  默认至少生成一个 react node 作为证据收集节点，除非用户明确要求多个独立标的或多个可分离交付物。
  如果同时加载了结构化股票/A股指标类 planner skill，并且它要求创建 market_data.md 节点，应保留该结构化数据节点；本 skill 的 evidence_claims.md 节点负责补充公告、网页来源、公司业务、竞对格局、产品景气、行业地位、事件和风险证据。
  证据收集 node 应使用 mode=write，因为它需要写入内部 evidence artifact；但 objective 必须限定只创建 evidence_claims.md，不创建面向用户的报告或附件。
  证据收集 node 的 objective 必须要求：
  - 先确认证券身份：公司全称、股票代码、交易所；不能猜测未知股票代码。
  - 收集财务、行情估值、公司业务、主要产品、客户/下游应用、竞对格局、产品市场景气、公告事件、行业地位、风险依据等关键事实。
  - 对上市公司业务必须尽量拆到主要业务/产品线层面，而不是只写“公司属于某行业”；应关注收入构成、核心产品、下游场景和业务变化。
  - 对竞对现状必须说明可比公司或替代方案、竞争维度、竞争强弱依据；无法确认竞对时应标记待核验，不要凭常识编造。
  - 对产品市场景气必须寻找需求、价格、出货量、订单、库存、产能利用率、政策、资本开支或下游行业数据等证据；不要只用股价涨跌代表景气。
  - 每个关键事实形成 claim，并绑定至少一个来源 URL。
  - 数字、日期、公告、行情、估值、市占率、管理层、业务构成、竞对判断、产品景气和定性行业判断都必须有来源支撑。
  - 优先级：交易所/公司公告/定期报告 > 可靠行情或金融数据源 > 主流财经媒体 > 普通网页或自媒体。
  - 无可靠来源的事实不要写入确定 claim，可标记为 needs_verification 或直接省略。

  证据收集 node 的 output_hint 必须明确要求产出内部 artifact：evidence_claims.md。
  evidence_claims.md 使用 Markdown，不要写 JSON。推荐结构：
  - 标题：研究对象、当前日期、证据范围。
  - 按类别分节：证券身份、公司业务、财务数据、行情估值、竞对格局、产品市场景气、公告事件、行业地位、风险因素。
  - 每个分节使用 Markdown 表格记录：Claim、来源URL、来源标题、日期/期间、来源类型、置信度、备注。
  - 每条 Claim 必须在同一行包含可点击来源 URL；没有来源 URL 的硬事实不要写入表格。
  - 对低置信度或需要复核的信息，在备注中写明“待核验”或“不确定口径”。

  不要额外创建只用于“分析总结”的 node；最终总结和表达由 Aggregator 基于 evidence_claims.md 完成。
