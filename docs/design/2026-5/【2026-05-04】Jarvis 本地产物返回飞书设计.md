# Jarvis 本地产物返回飞书设计

日期：2026-05-04

## 背景

用户在飞书中请求：

```text
用codex画一个jarvis架构的svg
```

日志显示任务实际完成：

- `delegate_to_codex` 成功生成 `E:/pythonProject/jarvis/jarvis_architecture.svg`
- Codex 返回了本地文件路径和完成说明
- 飞书只更新了原“Thinking”交互卡片，发送的是 Markdown 文本

结果是：用户在飞书里只能看到“已保存到项目根目录”的文字，看不到生成的图片或文件。

## 问题定位

当前链路只传递文本，不传递本地产物。

### 1. 工具结果 artifacts 被丢弃

`ToolExecutionResult` 已经支持 `artifacts: list[str]`，但 ReAct 执行层的 `_execute_single_tool()` 只返回：

```python
(ok, output)
```

因此工具产物不会进入后续 runtime、最终回复或渠道层。

### 2. TurnResult / ChannelMessage 没有附件协议

`ChannelMessage` 当前主要字段是：

```python
content
content_type
summary
metadata
```

虽然有 `metadata`，但没有约定 `attachments` 结构，也没有收集本轮 tool artifacts 的逻辑。

### 3. 飞书通道只支持文本和交互卡片

`FeishuChannel` 当前发送链路是：

```text
ChannelMessage -> FeishuRenderer.render() -> text / interactive card
```

没有：

- 上传本地图片拿 `image_key`
- 发送 `msg_type=image`
- 上传文件拿 `file_key`
- 在卡片中追加 `img` 元素

### 4. SVG 需要特殊处理

飞书图片上传更适合 PNG/JPG/WebP 等位图。SVG 作为矢量源码，适合保留为文件或链接，但不一定适合作为图片预览直接上传。

因此 SVG 产物应先渲染成 PNG 预览，再把 PNG 发到飞书；SVG 原文件可作为文本路径或后续文件附件保留。

## 目标

让 Jarvis 在飞书中完成“生成图片/文件”的请求时，用户能直接收到可查看的产物，而不是只收到本地路径。

目标行为：

1. 工具生成本地图片后，Jarvis 自动识别产物。
2. 对 PNG/JPG/WebP/GIF 等图片，上传并发送到飞书。
3. 对 SVG，生成 PNG 预览后上传，同时保留 SVG 本地路径说明。
4. 文本回复仍保留，说明文件保存位置、验证结果和限制。
5. 日志能区分“生成成功但上传失败”和“生成失败”。

## 非目标

本轮不设计公开文件下载服务。

不把任意本地路径暴露给飞书上传，只允许上传安全白名单路径下的产物。

不把所有 artifact 都作为飞书附件发送，先支持图片类产物。

## 设计方案

### 1. 引入 ToolExecutionOutcome

将 `_execute_single_tool()` 从 tuple 返回改为结构化对象：

```python
@dataclass(frozen=True)
class ToolExecutionOutcome:
    ok: bool
    output: str
    artifacts: tuple[str, ...] = ()
```

执行工具后保留 `ToolExecutionResult.artifacts`。

对 `delegate_to_codex`，即使工具返回 `ok=False` 但内容是审批请求，也仍按现有逻辑作为可继续的输出处理，但 artifacts 仍需要保留。

### 2. ToolMessage raw_payload 记录 artifacts

工具消息追加时，将 artifacts 写入 raw_payload：

```python
raw_payload={
    "source": "agent_react.tool_result",
    "tool_name": tool_name,
    "tool_call_id": tool_call_id,
    "artifacts": list(outcome.artifacts),
}
```

这样 runtime 可以从本轮消息中收集产物，审计也能追踪。

### 3. Runtime 汇总附件

`TurnRuntime._finalize()` 在生成 `ChannelMessage` 前，从本轮 tool messages 中收集 artifacts，并规范化为：

```python
metadata={
    "attachments": [
        {
            "kind": "image",
            "path": "E:/pythonProject/jarvis/jarvis_architecture.png",
            "source_path": "E:/pythonProject/jarvis/jarvis_architecture.svg",
            "mime_type": "image/png",
        }
    ]
}
```

识别规则：

- `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif` -> image
- `.svg` -> image source，需要预览转换

安全规则：

- 路径必须 resolve 到注册仓库根目录、`data/coder-runs` 或明确允许的运行产物目录内
- 文件必须存在
- 文件大小必须低于配置限制，例如 20 MB
- 不上传 `.env`、`data/` 下敏感内容、日志、数据库、密钥文件

### 4. SVG 转 PNG 预览

新增一个轻量转换 helper：

```text
svg -> png preview
```

可选实现：

- 优先使用已安装的 `cairosvg`
- 如果没有依赖，则先只作为文件路径展示，并在日志中记录 `svg_preview_unavailable`

建议单独配置依赖，不要在运行时临时安装。

### 5. Feishu 发送图片附件

在 `FeishuChannel` 中增加附件发送流程：

```text
1. 先更新/发送文本卡片
2. 再逐个发送附件
```

图片发送：

```text
local image -> /im/v1/images upload -> image_key -> /im/v1/messages msg_type=image
```

后续也可改为把图片作为卡片 `img` 元素合并到最终 interactive card，但首版建议额外发送一条图片消息，失败面更小。

### 6. 日志与错误处理

新增关键日志：

```text
artifact detected turn_id=... path=... kind=image
artifact rejected turn_id=... path=... reason=...
feishu image upload starting path=...
feishu image upload completed image_key=...
feishu image message sent receive_id=...
feishu image send failed path=... error=...
```

如果文本卡片发送成功但图片上传失败，最终仍应给用户一条文本提示：

```text
图片已生成到本地，但上传飞书失败：...
```

## 推荐实施顺序

1. ReAct 层保留工具 artifacts。
2. Runtime 汇总本轮附件到 `ChannelMessage.metadata.attachments`。
3. Feishu 支持上传并发送 PNG/JPG/WebP/GIF。
4. 增加 SVG -> PNG 预览。
5. 补日志和测试。

## 测试计划

单元测试：

- 工具返回 artifacts 时，ToolMessage raw_payload 保留 artifacts。
- Runtime 能从本轮 tool messages 汇总图片附件。
- 非白名单路径被拒绝。
- `.svg` 能生成 PNG 预览或在缺少转换依赖时降级。
- Feishu 图片上传成功后发送 `msg_type=image`。
- 图片发送失败不影响文本回复。

集成测试：

- 模拟 Codex 生成 `jarvis_architecture.svg`
- Runtime 最终回复包含文本说明和 image attachment
- Feishu 通道先更新卡片，再发送图片消息

## 当前事件结论

这次问题不是 Codex 没生成图片，而是 Jarvis 缺少：

```text
本地生成产物 -> runtime attachment -> 飞书上传/发送
```

的完整链路。

修复后，类似“画图/生成 SVG/生成 PNG”的任务应该在飞书里直接返回可查看的图片，同时保留本地文件路径作为补充信息。
